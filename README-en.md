## Install

Not published on NuGet. Clone the repository and add a project reference. **.NET 8 or newer** is required.

```bash
git clone https://github.com/amanetoki7/twikit-dotnet.git
```

```xml
<ItemGroup>
  <ProjectReference Include="path/to/twikit-dotnet/src/Twikit/Twikit.csproj" />
</ItemGroup>
```

To distribute it as a package, `dotnet pack src/Twikit/Twikit.csproj -c Release` produces a `.nupkg`.

## Quick start

> [!IMPORTANT]
> **Log in with cookies, not with a password.**
> X has retired the onboarding flow that `Client.LoginAsync()` drives — it answers `code 366, "flow name LoginFlow is currently not accessible"`. Verified against live x.com on 2026-07-29: `/i/flow/login` now redirects to `/i/jf/onboarding/web`, and the site posts to `/i/jfapi/onboarding/web/actions/begin_login`, which requires a ~5 KB `$castle_token` generated by obfuscated in-page JavaScript and offers passkey/WebAuthn as a first factor. None of that is reachable from a plain HTTP client, so **password login cannot be made to work** — it throws `LoginRetiredException`. Export your cookies from a browser session instead.

**Getting the cookies**: log in to x.com in a browser, open the developer tools (Application / Storage → Cookies) and copy the values of `auth_token` and `ct0`. Those two are enough.

**Create a client and load cookies.**

```csharp
using Twikit;

var client = new Client("en-US");

// auth_token and ct0 are enough
client.SetCookies(new Dictionary<string, string> { ["auth_token"] = "...", ["ct0"] = "..." });
// or: client.LoadCookies("cookies.json");

if (!await client.IsLoggedInAsync())
    throw new Exception("Cookies are stale - export them again.");

// keep them for next time
client.SaveCookies("cookies.json");
```

`SetCookies` also accepts the list format exported by browser extensions or Playwright (an array of objects with `name` and `value`) as a `JsonNode`.

**Post a tweet with media attached.**

```csharp
var mediaIds = new List<string>
{
    await client.UploadMediaAsync("media1.jpg"),
    await client.UploadMediaAsync("media2.jpg"),
};
await client.CreateTweetAsync("Example Tweet", mediaIds);
```

**Search the latest tweets for a keyword.**

```csharp
var tweets = await client.SearchTweetAsync("python", "Latest");
foreach (var tweet in tweets)
    Console.WriteLine($"{tweet.User?.Name}: {tweet.Text} ({tweet.CreatedAt})");

var more = await tweets.NextAsync();   // next page
```

**A few more common calls.**

```csharp
await client.GetUserTweetsAsync("123456", "Tweets");   // a user's tweets
await client.SendDmAsync("123456789", "Hello");         // send a DM
await client.GetTrendsAsync("trending");                // trending topics
```

### Running the examples

[examples/Twikit.Examples](examples/Twikit.Examples) is a single console app; the first argument picks the example. Pass the cookies through the `AUTH_TOKEN` and `CT0` environment variables (they are saved to `cookies.json` on the first run and reused after that).

```bash
AUTH_TOKEN=... CT0=... dotnet run --project examples/Twikit.Examples -- basic
```

| Argument | What it does |
|---|---|
| `basic` | Search, look up users, read tweets — the basics |
| `download-media` | Download the media attached to a tweet |
| `listen` | Watch a user for new tweets |
| `dm-auto-reply` | Reply to incoming DMs automatically |
| `delete-all` | Delete every tweet on your account |
| `spaces` | X Spaces demo |
| `guest` | Guest client (currently closed on X's side) |

## Features

- **No API key** — works by scraping the web client.
- **Free & open source** (MIT).
- Tweets, search, timelines, trends, users, DMs, media, bookmarks, lists, communities, notifications, streaming — every public API of the Python version.
- **X Spaces** — read, search, create, publish, moderate and end audio Spaces, HLS stream URLs, chat history and live chat (WebSocket). No extra packages needed; only WebRTC voice requires an `IPeerConnectionFactory` implementation (see below). See [docs/articles/spaces.md](docs/articles/spaces.md) and [SpacesExample.cs](examples/Twikit.Examples/SpacesExample.cs):

  ```csharp
  var space = await client.Spaces.GetSpaceAsync("1DXGydznBYWKM");
  var stream = await client.Spaces.GetStreamAsync(space.MediaKey!);   // HLS url
  var chat = await client.Spaces.ChatAsync(space);                     // history
  var created = await client.Spaces.CreateSpaceAsync(title: "hi");     // go live
  await client.Spaces.EndSpaceAsync(created["broadcast"]!["id"]!.GetValue<string>());
  ```

### What is fixed compared to upstream twikit

The last upstream release (`twikit==2.3.3`) is broken in several ways as of 2026. This library is a port of the Python fork that carries the twifork fixes, so the following upstream issues do not occur here (each item links to the upstream issue):

- **ClientTransaction / `Couldn't get KEY_BYTE indices`** — updated `ondemand.s.js` parsing for the new X webpack bundle, so GraphQL requests work. ([#408](https://github.com/d60/twikit/issues/408), [#409](https://github.com/d60/twikit/issues/409), [#304](https://github.com/d60/twikit/issues/304))
- **Intermittent / sticky `404`** — the `X-Client-Transaction-Id` animation key was missing a rounding step that X performs; it is restored. Long-running processes can redo the handshake with `client.RefreshTransaction()`. ([#357](https://github.com/d60/twikit/issues/357), [#397](https://github.com/d60/twikit/issues/397))
- **Crashes on missing optional fields, empty user `Name` / `ScreenName`** — X moved `name`, `screen_name`, `created_at`, avatar and more out of `legacy` into new sub-objects; these are read from the new location with a `legacy` fallback, and missing keys are treated as null. ([#417](https://github.com/d60/twikit/issues/417))
- **`GetTweetByIdAsync` missing `itemContent`**, **`GetUserTweetsAsync` on accounts with no tweets** — both the legacy and the new trailing-cursor shapes are handled, and empty / cursor-less timelines return an empty result. ([#332](https://github.com/d60/twikit/issues/332), [#363](https://github.com/d60/twikit/issues/363), [#361](https://github.com/d60/twikit/issues/361), [#216](https://github.com/d60/twikit/issues/216))
- **`GetTrendsAsync` returns nothing** — rebuilt on top of `GenericTimelineById`, with `GetExplorePageAsync()` added. Unbounded retries and empty news / sports / entertainment categories are fixed too. ([#389](https://github.com/d60/twikit/issues/389))
- **`GetLatestFriendsAsync` 404** — uses the GraphQL `Following` endpoint after the v1.1 endpoint was retired. ([#397](https://github.com/d60/twikit/issues/397))
- **The captcha unlock path** ([#333](https://github.com/d60/twikit/issues/333)) and **the infinite loop in `GetBookmarkFoldersAsync` pagination** ([#334](https://github.com/d60/twikit/issues/334), [#335](https://github.com/d60/twikit/issues/335)) are fixed.
- **`GetLatestTimelineAsync` / `GetListTweetsAsync` dropping conversation entries** — home and list conversation entries are unpacked. ([#336](https://github.com/d60/twikit/issues/336), [#337](https://github.com/d60/twikit/issues/337), [#340](https://github.com/d60/twikit/issues/340))
- **Pagination** — `NextAsync()` no longer re-requests the same page when X omits the cursor. `count` is honoured; the surplus X over-delivers is handed back through `NextAsync()`.
- **Replies tab and DMs** — `GetUserTweetsAsync(..., "Replies")` returned the other party's tweet instead of the user's own reply; pinned tweets were dropped or duplicated; `SendDmAsync` reported the wrong sender.
- **X's refusals are raised, not hidden** — permission errors (code 37 and friends) no longer come back as an empty result, `CreateTweetAsync` surfaces X's daily-limit message verbatim, and unresolvable lists / users throw `NotFoundException` / `UserNotFoundException` instead of returning an empty object.
- **Notifications** — `GetNotificationsAsync("Mentions")` handles the new payload without a `notifications` key.
- **New properties** — `Media.SourceUrl` for the full-resolution image ([#376](https://github.com/d60/twikit/issues/376)), `Tweet.QuotedStatusId` for the quoted tweet id ([#222](https://github.com/d60/twikit/issues/222)), plus `Tweet.Url`, `Tweet.Article`, `Tweet.Source`, `Tweet.ConversationIds`, `User.VerifiedType`, the parody / automated labels, `Conversation`, `Message.ReplyData` and more.
- **Endpoints** — GraphQL query ids and feature flags refreshed to their 2026 values.

`GuestClient` is ported too, but guest access is closed on X's side, so `ActivateAsync()` throws `InvalidSessionException`: a logged-out request only ever gets a ~34 KB page shell with no webpack manifest, so the `X-Client-Transaction-Id` handshake cannot complete. No library fix changes that — use cookies. ([#192](https://github.com/d60/twikit/issues/192)) Likewise, problems caused by X-side restrictions (account suspension, Cloudflare / IP blocks, captcha, automation limits) are out of scope.

### API added on top of upstream

- `Client.IsLoggedInAsync()` — checks whether the cookies still authenticate.
- `Client.RateLimitRemaining` / `Client.RateLimitReset` — the rate-limit budget reported by the last response.
- `Client.RefreshTransaction()` — redo the `X-Client-Transaction-Id` handshake.
- `Client.GetDmInboxAsync()`, `CreateGroupAsync()`, `DeleteDmConversationAsync()` — the DM inbox, group creation and conversation deletion.
- `Client.UpdateProfileAsync()`, `GetAboutAccountAsync()`, `GetUserSpotlightsAsync()`, `GetUserListsAsync()`, `GetMutedUsersAsync()`, `GetBlockedUsersAsync()`.
- `Client.GetUserMentionsAsync()`, `SearchTweetsByDateAsync()`, `GetThreadAsync()`, `GetTweetByUrlAsync()`, `GetExplorePageAsync()`.
- `SearchOptions` / `SearchQuery.Build` — search query building.
- `Article`, `Conversation` — long-form articles and DM conversations.
- The `Twikit.Spaces` namespace — the Spaces classes (`Spaces`, `Space`, `SpaceChat`, `SpaceVoiceSession`, ...).
- Exceptions: `ClientTransactionException`, `InvalidSessionException` (cookies rejected), `LoginRetiredException` (password login is gone).

## Differences from the Python version

- **There is no `impersonate=`** (browser TLS impersonation via curl_cffi). .NET has no equivalent built in, so instead you can plug in your own `HttpMessageHandler` with `new Client(handler: ...)`. A proxy is passed as `new Client("en-US", proxy: "http://user:pass@127.0.0.1:8080")` (`socks5://` works too).
- **X Spaces voice (WebRTC)** — .NET has no built-in WebRTC implementation, so the library exposes the `IPeerConnection` / `IPeerConnectionFactory` interfaces. Implement them with [SIPSorcery](https://github.com/sipsorcery-org/sipsorcery) or similar and pass them to `SpeakAsync` / `HostAsync` / `ListenAsync`. Metadata, search, create, end, moderation and chat work without any implementation.
- **`List` is called `TwitterList`** to avoid clashing with `System.Collections.Generic.List<T>`.
- Exceptions carry the `...Exception` suffix (`NotFoundException` and so on). The base class is `TwitterException`, as in Python.
- Methods that return a collection return `Result<T>` (an `IReadOnlyList<T>`); `NextAsync()` / `PreviousAsync()` fetch the neighbouring pages. Streaming is an `IAsyncEnumerable`, read with `await foreach`.

The remaining small differences are listed in [docs/articles/python-differences.md](docs/articles/python-differences.md).

## Build and test

```bash
dotnet build Twikit.sln -c Release
dotnet test tests/Twikit.Tests -c Release
```

The tests never touch the network. The `X-Client-Transaction-Id` math (animation key, `float_to_hex`, cubic Bézier, Python-compatible rounding) is checked bit-for-bit against [tests/Twikit.Tests/Fixtures](tests/Twikit.Tests/Fixtures), which were generated with the Python implementation. [`.github/workflows/dotnet.yml`](.github/workflows/dotnet.yml) runs the same build and tests on every push and pull request.

## Protecting your account

This library uses the unofficial API, so careless use can get an account suspended. Don't send too many requests, reuse your cookies, and follow the other advice in [docs/articles/protect-account.md](docs/articles/protect-account.md) (Japanese).
